# Design

## Surface

Тихий дом, сервис оформления и сопровождения похорон. Интерфейс должен снижать тревогу, показывать стоимость и состав без давления.

## Visual register

Спокойный, честный, человеческий. Не юридическая фирма, не риелторский сервис, не SaaS-лендинг.

## Color

- Основа: тёплые белые и серые поверхности, без чистого `#fff` и `#000` в новых компонентах.
- Акцент: синий `#1794FD`, только для focus, выбранного состояния и редких ключевых действий.
- Ошибки: спокойный красный фон, текст читаемый, без агрессивной срочности.

## Typography

- Основной текст: минимум 16 px на мобильном.
- Вторичный текст: минимум 14 px, кроме коротких служебных labels.
- Цифры цен: tabular nums, без декоративных градиентов.
- Не использовать длинные uppercase-блоки. Uppercase только для коротких labels.

## Components

- Tap targets: минимум 44 × 44 px.
- Primary buttons: компактные, не “огромные пилюли”.
- Info marker `i`: маленький hover/focus tooltip, не CTA-кнопка.
- Cards: использовать только когда карточка реально помогает сравнению. Избегать бесконечной сетки одинаковых карточек.
- Modals: только когда нужен отдельный focused view. Для мелких пояснений использовать tooltip или inline disclosure.

## Motion

- Motion короткий: 150-260 ms.
- Animate opacity, transform, grid rows. Не animate layout height.
- `prefers-reduced-motion` обязан выключать декоративную motion.

## Copy

- Не обещать “лучший”, “премиальный”, “под ключ” без конкретики.
- Показывать, что делает координатор, что подтверждает семья, что меняется только после согласования.
- Не использовать срочность и давление.
- Для save-plan: “план сохранён”, не “заказ оформлен”, не “оплата”.

## Packages page rules

- Тариф `86 600 ₽`: база внутри блока состава.
- Настройка тарифа: 4 шага максимум, sticky итог виден при выборе.
- Готовые решения: без отдельного слоя “быстрое сравнение”, главное отличие находится внутри каждой карточки.
- Telegram/email save должны сохранять фактический состав и итоговую сумму.
- Email save не должен показывать депозит, договор или checkout.

## Guide/articles rules

- Справочник начинается с ситуации пользователя, а не с общей сетки статей.
- На главной показывать 2-3 важных маршрута чтения, без декоративных обложек ради обложек.
- Карточки статей должны быть плотными: вопрос, польза, время чтения, переход.
- Верхний поиск обязан вести к тарифам, справочнику и ключевым статьям, включая переходы с внутренних страниц.

## Accessibility

- WCAG 2.2 AA target.
- Все интерактивные элементы: visible focus.
- Tooltip доступен по hover и keyboard focus.
- Dynamic price/status changes use `aria-live` where useful.
- Mobile 320/375/390/430 px must have no horizontal body overflow.
